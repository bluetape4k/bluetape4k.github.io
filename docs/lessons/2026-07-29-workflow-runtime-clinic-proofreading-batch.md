## 교정에서 확인한 경계

### 기계 식별자와 독자용 설명은 분리해야 한다

`run`, `lane`, `lane-start`, `owner_epoch`처럼 상태 파일과 명령에서 실제로
사용하는 이름은 코드 표기로 보존했다. 반면 본문과 다이어그램의 일반 명사는
`전체 작업`, `실행 단위`, `소유권 세대`로 설명했다. 식별자를 번역하면 소스와
대조하기 어렵고, 모든 설명을 영어로 두면 한국어 기술 글의 흐름이 끊긴다.

### 과거 릴리스 재현과 현재 설치 절차는 같은 문단에 섞지 않는다

런타임 글은 `v1.1.0`의 설계와 동작을 설명한다. 이 역사적 근거는 유지하되,
독자가 지금 설치할 때는 현재 안정 버전 `v1.2.2`를 사용하도록 절차를 분리했다.
현재 설치 명령이 과거 글의 공개 시점과 계약을 덮어쓰지 않도록 각각의 태그와
용도를 명시했다.

### 문장만 자연스러워도 계약은 오래될 수 있다

현재 `bluetape-workflow` 원본을 다시 대조하니 공통 검증 관문은 기존 글의
17개가 아니라 `CG-01`부터 `CG-18`까지 18개였다. 교정은 표현을 다듬는 작업에
그치지 않는다. 변경 가능한 개수, 상태, 제한 시간, 역할 구분은 현재 원본이나
해당 릴리스 태그에 다시 묶어야 한다.

### 다크 스타일은 배경색만 바꾸는 작업이 아니다

첫 변환에서는 캔버스는 어두워졌지만 일부 카드 내부의 글자 대비가 충분하지
않았다. 카드·레이블 상자·범례·바닥글의 채움색과 글자색을 각각 확인하고,
CairoSVG로 만든 2배 PNG를 원본 크기로 다시 보아야 했다.

### 지역화 생성기는 두 번 실행해도 결과가 같아야 한다

문구 치환을 다시 실행하면서 `범위가 제한된 할당`이
`범위가 범위가 범위가 제한된 할당`으로 누적되는 결함을 발견했다. 치환 뒤
표현을 정규화하고, 생성기를 연속 두 번 실행한 뒤 자산 체크섬이 같은지
검증하는 절차를 추가했다.

## 체크리스트 반영

위 다섯 규칙을 chezmoi 원본의 `bluetape-writer` 한국어 자연스러움
체크리스트에 추가했다. `chezmoi apply`, 원본·실제 파일 SHA-256 일치,
Codex 자체 점검, dotfiles `main` 푸시까지 완료했다.

## 다음 배치에 적용할 항목

1. 작업 시작 전에 갱신된 실제 체크리스트를 다시 읽는다.
2. 기계 식별자와 설명 용어를 별도 목록으로 고정한다.
3. 변경 가능한 계약은 현재 원본과 역사적 태그를 나누어 대조한다.
4. 다크 변환 뒤 한영 PNG를 각각 원본 크기로 확인한다.
5. 생성기를 두 번 실행하고 출력 체크섬이 같은지 확인한다.

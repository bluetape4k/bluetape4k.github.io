# 시각 자료는 저장소별 기본 Card에 배치한다

## 배경

2.0 신규 기능 시각 자료를 1차와 2차 작업으로 나눠 제작하면서, 작업 묶음마다 별도 Wave 허브를 만드는 구성을 시도했다. 그러나 이 사이트의 기존 탐색 기준은 작업 차수나 Epic이 아니라 원본 저장소다. 별도 허브는 같은 저장소의 시각 자료를 여러 진입점으로 나누고, 기본 시각 자료 목록과 중복되는 탐색 구조를 만들었다.

## 결정

`/visual-companions/`를 유일한 목록 진입점으로 유지하고, 각 시각 자료는 원본 저장소의 기본 Card 영역에 배치한다. 같은 저장소에서 여러 이슈로 만든 자료는 하나의 저장소 섹션에 함께 노출한다. 작업 차수나 Epic 전용 허브는 사용자가 명시적으로 요구한 경우에만 추가한다.

이번 변경에서는 다음 원칙을 적용했다.

- `bluetape4k-projects`, `bluetape4k-aws`, `bluetape4k-image`별로 Card를 묶는다.
- Epic 1의 SQS와 Epic 2의 Streams 자료는 모두 `bluetape4k-aws` 섹션에 둔다.
- Wave 1·2 허브와 그 링크는 제거하되, 개별 EN/KO 시각 자료 경로는 유지한다.
- Card는 대화형 페이지와 정적 SVG·PNG로 직접 연결한다.

## 재발 방지

새 시각 자료의 탐색 구조를 바꾸기 전에 기존 카탈로그의 분류 기준을 확인한다. 이슈나 Epic의 작업 관리 구조를 사이트 정보 구조로 그대로 옮기지 않는다. 구현 테스트에서는 repo별 그룹과 정확한 locale 경로를 확인하고, 요청하지 않은 별도 허브 경로가 생성되지 않는지도 함께 검증한다.

## 검증 기준

- 각 시각 자료가 원본 저장소의 기본 Card 아래에 나타난다.
- EN/KO Card가 각 locale의 정확한 대화형 경로를 가리킨다.
- 제거한 Wave 허브 경로는 빌드 결과에 존재하지 않는다.
- 기존 개별 대화형 페이지와 정적 자산 경로는 그대로 유효하다.

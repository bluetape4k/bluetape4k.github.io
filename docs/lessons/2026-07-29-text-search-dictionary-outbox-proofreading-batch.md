## 사실과 경계 검증

- `matchesAsFlow`의 기본 옵션 경로는 자동 장치를 순회하면서 일치 항목을 방출하고 `take(N)` 취소에 협력한다. 그러나 겹침 제거 또는 단어 경계 필터가 필요하면 전체 결과를 후처리하므로, `Flow` 반환형만 보고 모든 옵션이 점진 처리된다고 설명해서는 안 된다.
- 런타임 사전 추가 API는 현재 프로세스의 메모리만 바꾼다. 영속 저장, 재시작 복구, 제거, 다중 인스턴스 전파는 서비스가 별도로 설계해야 한다.
- 멱등성 키의 선행 조회는 빠른 경로일 뿐 동시 요청 경합을 닫지 못한다. DB 고유 인덱스가 최종 쓰기 경계를 지키고, 제약 조건 충돌에서 커밋된 기존 행을 다시 읽어야 같은 결과를 반환할 수 있다.
- 트랜잭셔널 아웃박스는 도메인 행과 아웃박스 행의 원자성은 보장하지만 외부 전달까지 하나의 트랜잭션으로 만들지는 않는다. 커밋 이후 전달 실패는 저장된 상태와 재시도 횟수로 복구해야 한다.
- 실시간 아웃박스의 `replayAfter`는 발행된 행을 커서 이후부터 다시 읽는 경계다. 개별 WebSocket/SSE 클라이언트의 실제 수신 보장은 별도의 확인 또는 오프셋 정책이 필요하다.

## 한국어 교정 교훈

- 식별자가 아닌 일반 설명에서는 `keyword`, `match`, `automaton`, `post-processing`을 각각 `키워드`, `일치 항목`, `자동 장치`, `후처리`처럼 출판용 기술 한국어로 쓴다.
- `runtime add API`, `process memory`, `multi-instance rollout`은 `런타임 추가 API`, `프로세스 메모리`, `다중 인스턴스 반영`처럼 의미를 보존하면서 문장 구조를 한국어로 바꾼다.
- `row`, `commit`, `rollback`, `retryable failure`, `failure contract` 같은 일반 설명은 `행`, `커밋`, `롤백`, `재시도 가능한 실패`, `실패 계약`으로 통일하고, 코드 식별자와 상태값은 원문을 유지한다.
- “정상 경로가 예쁘다”, “서비스가 평화롭게 뜬다”, “재시도는 평범한 트래픽이다” 같은 번역체·구어체 평가는 제거하고 관찰 가능한 상태와 운영 경계를 직접 설명한다.
- 독자용 자료에는 모듈, 서비스, 저장소와 대표 테스트 링크를 남기되 내부 이슈·계획·작업 기록은 제외한다.

## 다이어그램 교훈

- 정적 감사 전 원본 크기 시각 검수에서 영어 카드 제목 넘침과 폭이 지나치게 좁은 재시도 원장 카드를 발견했다. 언어별 제목 글꼴과 하단 카드 배치를 조정해 본문·연결선 겹침을 제거했다.
- 시퀀스 다이어그램의 프레임 제목과 첫 메시지 라벨은 서로 다른 수직 구간을 사용해야 한다. 메시지 행을 아래로 이동하고 활성 구간 끝점 안에 화살표를 배치해 라벨 겹침과 endpoint 실패를 함께 해결했다.
- 하단 재시도 순환선은 카드 내부를 지나지 않도록 별도 직교 경로로 배치했으며, 한영 자산 모두 `shared_segments=0`, 대각선 0, endpoint 실패 0을 유지했다.
- 4개 stem의 KO/EN SVG 8개와 CairoSVG 2배 PNG 8개를 원본 크기로 확인하고, 구조도와 시퀀스 다이어그램에 맞는 확대 제목을 각각 제공했다.

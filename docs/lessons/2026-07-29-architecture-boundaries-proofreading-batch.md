# 아키텍처 경계 글 교정 교훈

## 범위

- JaVers Part 4: 감사 저장 비용과 벤치마크 해석
- Spring Modulith 발행 기록과 트랜잭셔널 아웃박스의 경계
- Spring WebFlux 멀티테넌시의 컨텍스트 전파와 테넌트 온보딩
- 한영 기술 다이어그램 7종, 총 14개 SVG/PNG 자산

## 교정에서 확인한 사실 경계

### 같은 데이터베이스 행이라도 복구 책임은 다르다

Spring Modulith 발행 기록은 같은 애플리케이션 안에서 로컬 리스너가
완료됐는지 추적한다. 트랜잭셔널 아웃박스는 외부 실행 환경으로 전달할
의도를 기록한다. 둘 다 행을 남긴다는 이유로 발행 기록을 “가벼운
아웃박스”라고 부르면 실패를 복구할 주체와 범위가 흐려진다.

글에서는 원래 트랜잭션 안에서 주문과 리스너별 발행 기록이 저장되고,
커밋 뒤 리스너가 실행된다는 순서를 소스와 테스트로 확인했다. 한국어
본문과 다이어그램에서는 일반 용어를 `발행 기록`, `재실행`, `아웃박스`로
통일하고 `EventPublicationRepository`, `EVENT_PUBLICATION`,
`IncompleteEventPublications` 같은 식별자는 그대로 보존했다.

### 멀티테넌시는 전달보다 공개 시점이 먼저다

`X-TENANT-ID`를 해석했다는 사실은 요청자가 그 테넌트에 접근할 수 있다는
뜻이 아니다. 또한 영속 생명주기 상태가 `ACTIVE`라는 사실만으로 현재
프로세스가 해당 자원을 안전하게 라우팅할 수 있는 것도 아니다.

따라서 글과 다이어그램은 식별, 인증, 권한 검증, 컨텍스트 공개,
트랜잭션에서의 DB 선택, 준비 상태 검사와 런타임 레지스트리 게시를
분리했다. 테스트 의사코드도 `given/when/then/and`를 그대로 두지 않고
`준비/실행/검증/그리고`로 바꿔 한국어 기술 문서의 절차로 읽히게 했다.

### 벤치마크 숫자는 수행한 작업의 경계 안에서만 읽는다

JaVers 인메모리, Exposed 저장소, Exposed DDD, Hibernate Envers 경로는
같은 이름의 삽입·갱신·조회라도 포함하는 작업이 다르다. 저장소 경로는
전체 스냅숏 인코딩, 커밋 메타데이터 확인·삽입, 스냅숏 행 삽입을 포함한다.
Kafka 저장소도 현재 구현에서는 즉시 반환하는 단순 발행이 아니라 최대
30초 동안 브로커 발행 확인 응답을 기다린다.

본문의 영문 의사코드와 일반 명사를 한국어로 고치되, 측정값과 소스
식별자는 보존했다. 차트의 한영 숫자 12개씩도 서로 일치하는지 별도로
검사했다.

## 다이어그램 검증 교훈

한국어 다이어그램의 일반 영문 명사를 모두 번역해도 정확한 API 이름과
상태 값은 남겨야 한다. `tenant`, `context`, `registry`, `carrier`,
`probe`, `schema`는 각각 테넌트, 컨텍스트, 레지스트리, 전달 수단,
준비 상태 검사, 스키마로 바꿨다. `Reactor Context`,
`ConnectionFactory`, `TenantId`, `PROVISIONING`, `ACTIVE`, `FAILED`는
구현 계약이므로 보존했다.

연결선이 있는 한영 다이어그램 10개는 카드 침범, 연결선 교차·공유 구간,
레이블 겹침, 대각선, 끝점, 혼합 모서리 감사를 통과했다. 시퀀스 형식의
4개 자산은 생명선·활성 막대·화살표가 모두 존재하는지 보조 검사했다.
차트 4개는 한영 숫자 일치를 확인했다. 전체 14개 PNG는 SVG 뷰박스의 정확히
2배 크기로 렌더링됐고, 생성기를 두 번 실행한 체크섬도 같았다.

## 체크리스트 반영

이번 배치에서 반복 사용할 두 규칙을 chezmoi 원본의 `bluetape-writer`
한국어 교정 체크리스트에 추가했다.

1. Spring Modulith의 로컬 리스너 발행 기록과 외부 전달용 아웃박스를
   원자성·실행 시점·복구 책임에 따라 구분한다.
2. 멀티테넌시 글과 다이어그램의 독자용 인프라 명사는 한국어로 쓰고,
   정확한 API 이름과 코드 식별자만 보존한다.

체크리스트는 chezmoi로 적용한 뒤 원본과 실제 파일의 SHA-256 일치를
확인했다. self-audit는 `PASS=7 WARN=0 FAIL=0`이었고, dotfiles `main`의
커밋 `ff36f7e`을 원격에 push했다. 전체 동기화 상태에는 이번 변경과
무관한 native subagent watchdog 테스트 파일의 기존 불일치 1건이
남아 있지만, 관리 대상 Codex 파일과 이번 체크리스트는 원본과 일치한다.

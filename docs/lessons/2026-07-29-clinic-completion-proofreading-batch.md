# 병원 예약 시리즈 완결 구간 교정 교훈

## 범위

- 병원 예약 Part 6: 휴진·장비 사용 불가와 재배정 경계
- Timefold Workshop: 계획 모델, Score 영속화, 승인 참조 설계
- 병원 예약 Part 7: 리뷰와 운영 증거가 만드는 다음 개발 주기
- 한영 기술 다이어그램 4종, 총 8개 SVG/PNG 자산

## 교정에서 확인한 사실 경계

### 해결된 경계와 남은 경계를 한 항목으로 묶으면 안 된다

Part 7의 기존 글은 동일 요청 재전송과 수용 인원 경쟁 조건을 모두 아직
해결하지 못한 예약 무결성 문제로 설명했다. 현재 `AppointmentService`는
예약과 멱등성 레코드를 같은 트랜잭션에 저장하고, 고유 키 경쟁에서 패한
요청도 커밋된 레코드를 다시 읽어 같은 결과로 수렴시킨다. 따라서 요청
재생에 대한 멱등성은 구현된 경계다.

반면 서로 다른 두 요청이 마지막 수용 인원을 동시에 차지하려는 경쟁은
별도 문제다. 허용 수량을 계산하는 규칙이 존재해도 동시 쓰기가 자동으로
직렬화되지는 않는다. 글과 표를 고쳐 구현된 요청 멱등성과 아직 남은 수용
인원 무결성을 분리했다.

### 참조 설계는 구현된 구성처럼 보이면 안 된다

Timefold 글의 카드-연결선 다이어그램에는 `OptimizationJobService`, 후보
저장소, 작업 저장소, 승인 서비스가 등장한다. 그러나 현재
`timefold-workshop`은 Exposed Score 컬럼 왕복을 검증할 뿐 이 서비스와
저장소를 구현하지 않는다.

본문에서만 “더 필요하다”고 설명하면 다이어그램만 본 독자는 현재 구성을
오해할 수 있다. 본문 제목과 도입 문장, `data-diagram-title`, 대체 텍스트,
캡션, SVG의 제목·설명·부제에 모두 참조 설계임을 표시했다. 제안 구조를
조건부 표현으로 설명하는 것도 같은 사실 경계에 속한다.

### 독자용 용어와 코드 식별자를 분리한다

`HardMediumSoftScore`, `Idempotency-Key`, `SolverManager` 같은 정확한
식별자는 유지했다. 반면 설명 문장과 한국어 다이어그램의 `Hard`,
`Medium`, `Soft`, `tenant`, `workflow`, `snapshot`은 각각 필수·중간·선호,
테넌트, 업무 흐름, 스냅숏으로 정리했다. 정확한 식별자를 보존한다는 이유로
주변의 일반 명사까지 영어로 남겨서는 안 된다.

## 다이어그램 검증 교훈

상호작용 지도와 시퀀스 다이어그램을 같은 형식으로 검사하면 잘못된 실패가
생긴다. 이번 Timefold 그림은 사용자가 선택한 카드-연결선 지도이므로 생명선,
활성 막대, 번호가 붙은 호출을 요구하는 시퀀스 전용 감사는 적용 대상이
아니다. 대신 일반 기하, 카드 침범, 연결선 교차, 공유 구간, 레이블 겹침,
끝점, 혼합 모서리 감사를 적용했다.

4개 한영 자산은 CairoSVG로 2배 렌더링하고 생성기를 연속 두 번 실행해 PNG
체크섬이 동일한지 확인했다. 전체 contact sheet에서는 한국어·영어 자산의
카드 폭, 연결선, 화살촉, 제목과 하단 설명을 함께 검토했다.

## 체크리스트 반영

이번 배치에서 반복 사용할 두 규칙을 chezmoi 원본의 `bluetape-writer`
한국어 교정 체크리스트에 추가했다.

1. 이전에 빠졌던 기능이 구현됐더라도 인접한 경계가 남아 있으면 해결된
   계약과 미해결 계약을 분리한다.
2. 미구현 참조 구조는 본문, 그림 제목, 캡션, 대체 텍스트와 다이어그램
   자체에 일관되게 표시한다.

체크리스트는 chezmoi로 적용한 뒤 원본과 실제 파일의 SHA-256 일치를
확인했다. self-audit는 `PASS=7 WARN=0 FAIL=0`이었고, dotfiles `main`의
커밋 `bfabd057`을 원격에 push했다.

## 검증

- 사이트 테스트: 전체 통과
- Astro 검사: 오류 0건
- 정적 빌드: 1,303페이지
- 수정한 한영 경로: 6개 모두 HTTP 200
- 외부 자료 링크: 36개 모두 정상 응답
- 다이어그램: 일반 기하·연결선·끝점·혼합 모서리 감사 통과
- 원래 공개 날짜: 3편 모두 기준 브랜치와 동일
- 로컬 프리뷰: `http://127.0.0.1:4343/`

첫 정적 빌드에서는 prerender 청크 하나를 찾지 못하는 일시적 오류가
발생했다. 같은 작업 트리에 실행 중인 빌드가 없고 디스크 여유가 충분함을
확인한 뒤 파일 변경 없이 단일 빌드를 다시 실행하자 완료됐다. 원인을
확정하지 못한 일회성 오류를 콘텐츠 수정으로 덮지 않고, 최종 단일 빌드의
성공 결과를 검증 근거로 남겼다.

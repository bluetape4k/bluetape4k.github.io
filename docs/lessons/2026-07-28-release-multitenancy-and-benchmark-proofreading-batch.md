# 릴리스·멀티테넌트·벤치마크 교정 배치 Lessons

## 범위

- `bluetape4k-dependencies-making-part3-release-train`
- `exposed-r2dbc-ktor-multitenant-routing-patterns`
- `exposed-batch-kotlinx-benchmark-methodology`
- 한국어·영어 글과 기술 다이어그램 6종의 KO/EN SVG·PNG

## 사실과 경계 검증

- 릴리스 트레인은 개발용 스냅샷 버전 행렬, 안정 릴리스 입력, 상위 BOM의 Maven Central 게시 확인, 중앙 BOM 게시 순서를 구분해야 한다.
- 스냅샷 저장소의 일시적 403 오류만 제한적으로 재시도한다. 테스트 실패, 404, 컴파일 실패, 바이너리 비호환은 재시도로 숨기지 않는다.
- 테넌트 헤더의 형식과 알려진 테넌트 여부를 확인하는 입력 검증은 접근 권한을 증명하지 않는다. 인증 주체의 권한과 테넌트 준비 상태는 데이터베이스 라우팅 전에 별도 경계에서 확인해야 한다.
- 벤치마크의 `ops/sec`는 항상 같은 작업 단위를 뜻하지 않는다. 이번 배치에서는 `dataSize`만큼의 행을 처리하는 배치 작업 전체의 완료 횟수이며 행 처리량이 아니다.
- `bluetape4k-dependencies`의 `1.3.1` 태그와 `bluetape4k-exposed`의 `1.11.0` 태그에서 문서가 인용한 체크리스트, 스크립트, 테스트, 벤치마크 수치와 소스 경로를 대조했다.

## 한국어 교정 교훈

- `release matrix`, `upstream artifact`, `missing-only release`처럼 식별자가 아닌 일반 설명은 `릴리스 버전 행렬`, `상위 아티팩트`, `아직 게시되지 않은 아티팩트만 배포`로 풀어 쓴다.
- `버그가 발호한다`, `그냥 넘기면 안 된다`, `조금 귀찮다` 같은 표현은 기술 보고서 문체에 맞지 않는다. 오류의 발생 조건, 검증 책임, 운영 비용을 직접 설명한다.
- 멀티테넌트 글은 식별 정보 추출, 입력 검증, 권한 검증, 테넌트 준비 상태, 상태 전달, 트랜잭션 경계의 대상 선택, 격리 검증을 서로 다른 단계로 설명한다.
- 벤치마크 글은 처리량과 지연 시간의 높고 낮음뿐 아니라 연산 1회의 범위와 연산당 작업량을 함께 정의한다.
- 독자용 자료에는 실제 구현을 이해하는 데 필요한 대표 소스와 안내서만 제공하고 작업 이슈 번호 같은 원시 작업 정보는 본문 메타데이터에서 제외한다.

## 다이어그램 교훈

- 차트 SVG에는 사용하지 않는 화살표 마커도 남기지 않는다. 커넥터 감사 도구는 정의만 된 마커도 구조 신호로 인식할 수 있다.
- 시퀀스 다이어그램은 참여자, 생명선, 활성 구간, 메시지 방향, 거부 경계를 모두 표시하고 `diagram-sequence-style-audit.py`와 endpoint 감사를 함께 통과해야 한다.
- 차트의 축과 하단 주석에는 `ops/sec`의 연산 단위를 표시해야 한다. 독자가 행 처리량으로 오해할 가능성을 대체 텍스트와 본문만으로 보완해서는 안 된다.
- `data-diagram-title`은 자식 이미지가 아니라 확대 UI가 인식하는 기술 다이어그램 `figure`에 둔다. 시퀀스와 차트는 각각 `bt4k-sequence`, `bt4k-chart`로 분류한다.
- SVG 생성 성공과 PNG 해상도 확인만으로는 충분하지 않다. KO/EN 12개 PNG를 contact sheet와 원본 크기로 확인해 잘림, 대비, 화살표 방향, 수치 라벨을 검토한다.

## 체크리스트 반영

- `bluetape-writer` 한국어 교정 체크리스트에 릴리스 재시도 분류, 멀티테넌트 권한 경계, 벤치마크 연산 단위 규칙을 추가했다.
- 기술 보고서에 부적절한 기존 교정 예시를 직접적인 실패·검증 설명으로 교체했다.
- chezmoi 원본을 수정하고 live skill에 적용해 source/live parity와 원격 저장소 동기화를 확인했다.

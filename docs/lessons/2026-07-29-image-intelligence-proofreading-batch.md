# 이미지 인텔리전스 글 교정 교훈

## 범위

- 이미지 인텔리전스 Part 1: 다중 분석 경계와 부분 실패
- 이미지 인텔리전스 Part 2: 입력 자격 판정과 단일 디코딩
- 한영 기술 다이어그램 5종, 총 10개 SVG/PNG 자산

## 교정에서 확인한 사실 경계

### 입력 자격 판정과 분석 결과는 다른 질문에 답한다

이미지 업로드를 “검증한다”는 한 단어만 쓰면 파일 형식, 디코딩 가능 여부,
OCR 정확도, QR 존재 여부가 같은 단계처럼 보인다. 현재 예제는 선언한
미디어 타입, 실제 파일 시그니처, 압축 크기, 이미지 크기와 픽셀 예산,
전체 디코딩을 차례로 확인해 분석을 시작할 수 있는 입력인지 판정한다.

이 판정을 통과해도 악성 파일이 아니거나 OCR이 정확하거나 QR 코드가
존재한다고 보장하지 않는다. 글과 다이어그램에서는 `입력 자격 판정`,
`파일 시그니처 확인`, `이미지 크기 탐색`, `전체 디코딩`, `분석 결과`를
구분해 각 단계가 보장하는 범위를 드러냈다.

### 단일 디코딩은 무복사 보장이 아니다

`QualifiedImage`는 업로드 바이트의 공통 판정과 전체 이미지 디코딩을
분석기마다 반복하지 않게 한다. 하지만 네이티브 OCR 엔진이나 이미지
라이브러리가 자체 입력 표현으로 변환할 때 발생하는 복사까지 없애지는
않는다. 따라서 글에서는 “분석기마다 반복하지 않는다”는 구현 불변식만
설명하고 무복사 구조로 확대 해석하지 않았다.

### 워크플로 완료와 분석 성공은 다른 상태다

각 병렬 작업은 `Completed`, `Empty`, `Unavailable`, `Failed` 중 하나를
`WorkContext`에 기록한 뒤 `WorkReport.Success`를 반환할 수 있다. 여기서
`Success`는 작업이 결과 계약을 이행했다는 뜻이며 모든 분석기가 값을
만들었다는 뜻이 아니다. 한국어 본문은 일반 용어인 `workflow`,
`provider`, `fixture`, `circuit breaker`를 각각 `워크플로`, `공급자`,
`픽스처`, `회로 차단기`로 정리하면서 코드 식별자와 상태 이름은 보존했다.

## 다이어그램 검증 교훈

한국어 다이어그램에 남아 있던 `SHARED QUALIFICATION`, `ANALYSIS LANE`,
`LOW-COST DECLARED GUARDS`, `SHARED IMMUTABLE INPUT` 같은 독자용 레이블을
한국어로 바꿨다. 반면 `QualifiedImage`, `ImmutableImage`,
`AggregateStatus`, `Completed`, `Empty`, `Unavailable`, `Failed`는
구현 계약이므로 그대로 유지했다.

한영 다이어그램 10개는 카드 침범, 연결선 교차·공유 구간, 대각선, 끝점,
혼합 모서리 검사를 통과했다. PNG는 SVG 뷰박스의 정확히 2배 크기로
생성했고, 생성기를 두 번 실행한 뒤 모든 자산의 SHA-256이 같음을 확인했다.
전체 자산을 한 연락처 시트로 만들어 한영 레이블, 글자 잘림, 대비와 여백도
육안으로 확인했다.

### 전체 말뭉치 감사에서 끝점 방향까지 확인해야 한다

이번 배치의 다이어그램만 통과시키는 데서 멈추지 않고 블로그 전체 기술
다이어그램을 다시 조사했다. 한글 글 88개와 영문 글 88개는 모두 대응하는
문서를 가지며, 기술 다이어그램은 173종, 언어별 SVG는 모두 346개였다.

전체 SVG의 기하, 연결선 침범·교차·공유 구간, 연결선 끝점, 혼합 모서리를
검사하자 캐시 전략 다이어그램 한 종의 한영 자산에서 같은 끝점 오류가
발견됐다. `READ_ONLY`에서 `RMap`으로 향하는 연결선은 카드에 닿았지만,
마지막 경로 명령이 곡선 구간에서 끝나 화살표가 카드 경계에 수직으로
진입한다는 불변식을 증명하지 못했다. 생성기에 짧은 수직 종단 구간을
추가하고 자산을 다시 생성했다.

같은 다이어그램의 한국어 판에는 `loader`, `writer`, `cache hit`,
`transaction boundary` 같은 독자용 일반 용어도 남아 있었다. 이를
`로더`, `라이터`, `캐시 히트`, `트랜잭션 경계`로 바꾸되
`JdbcCacheRepository`, `EntityMapLoader`, `READ_ONLY` 같은 구현
식별자는 유지했다. 수정 후 346개 SVG 전체가 네 가지 감사를 모두
통과했다.

## 체크리스트 반영

이번 배치에서 반복 사용할 규칙을 chezmoi 원본의 `bluetape-writer`
한국어 교정 체크리스트에 추가했다.

- 이미지 분석 글에서 모든 단계를 `검증`으로 뭉뚱그리지 않는다.
- 선언 정보, 실제 시그니처, 이미지 크기 탐색, 전체 디코딩, 입력 자격
  판정, 분석 결과를 실제 실행 경계에 맞춰 구분한다.
- 입력 자격 판정 통과를 악성 파일 안전성이나 분석 품질 보장으로 확대하지
  않는다.

체크리스트를 chezmoi로 적용한 뒤 원본과 실제 파일의 SHA-256 일치를
확인했다. self-audit는 `PASS=7 WARN=0 FAIL=0`, 워크플로 계약 검사는
문제 0건이었고, dotfiles `main`의 커밋 `14fa7e9`을 원격에 push했다.
전체 동기화 상태에는 이번 변경과 무관한 native subagent watchdog 테스트
파일의 기존 불일치 1건이 남아 있지만, 관리 대상 Codex 파일과 이번
체크리스트는 원본과 일치한다.

## 검증

- 사이트 테스트: 170개 모두 통과
- Astro 검사: 오류 0건, 기존 힌트 3건
- 정적 빌드: HTML 2,415개
- 수정한 한영 경로: 4개 모두 정적 산출물과 로컬 프리뷰에서 확인
- 외부 자료 링크: 고유 URL 9개 모두 HTTP 200
- 다이어그램: 연결선·기하·끝점·혼합 모서리 감사 통과
- PNG: SVG 뷰박스 대비 정확히 2배
- 생성기: 두 번 실행한 자산 체크섬 일치
- 원래 공개 날짜: 한영 4개 문서 모두 기준 브랜치와 동일
- 전체 말뭉치: 한글 88개와 영문 88개 문서의 대응 관계 확인
- 전체 기술 다이어그램: 173종, 언어별 SVG 346개 모두 기하·연결선·끝점·혼합 모서리 감사 통과

# 생태계와 GraphDB 글 교정 교훈

## 범위

- bluetape4k 생태계 소개 글
- GraphDB 도입 판단 글의 한영 문서와 벤치마크 차트
- 차트 수치, 단위, 범례, 대표 이미지 제외 규칙

## 교정 교훈

### 생태계 소개는 모듈 나열보다 선택 기준을 보여줘야 한다

모듈 이름을 연속해서 소개하면 독자가 실제로 어떤 문제에서 어느 영역을
살펴봐야 하는지 알기 어렵다. 교정에서는 기능을 나열하는 문장을 줄이고,
공통 기반·데이터 접근·분산 시스템·도메인 기능이 어떤 선택 질문에
답하는지 드러냈다. 정확한 모듈명은 식별자로 보존하되 설명 문장은 역할과
경계를 중심으로 구성한다.

### 벤치마크 차트는 측정 사실과 도입 판단을 분리한다

차트에 표시한 수치는 특정 조건에서 얻은 측정 결과다. 이를 곧바로 모든
환경의 성능 우위나 GraphDB 도입 근거로 확대하면 안 된다. 축 단위, 측정
대상, 값의 방향을 한영 자산에서 동일하게 유지하고, 본문에서는 관계 탐색
깊이와 질의 형태 같은 도입 조건을 별도로 설명해야 한다.

## 검증

- 한영 차트의 값·단위·범례 대응 확인
- SVG와 2배 PNG 렌더링 확인
- 기술 차트 크게 보기와 대표 이미지 제외 규칙 확인
- 사이트 테스트, 정적 빌드, 로컬 경로 확인

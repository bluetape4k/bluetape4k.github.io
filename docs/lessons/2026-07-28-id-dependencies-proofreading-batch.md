# ID 생성기·Dependencies 교정 배치 교훈

## 배경

이번 배치는 Go·Kotlin ID 생성기 비교 글과 `bluetape4k-dependencies 1.3.0`
활용기 Part 1을 교정했다. 두 글 모두 시간이 지나도 유효한 설계 원칙과 특정
시점에만 유효한 구현·버전·벤치마크 정보를 함께 담고 있었다. 현재 소스를
참조하되 과거 측정값과 릴리스 구성을 현재 상태로 소급해서 바꾸지 않는 것이
핵심 검증 경계였다.

## 확인한 교정 원칙

### 현재 API와 과거 벤치마크를 분리한다

- 코드 예제는 현재 생성자와 메서드 시그니처를 따르며, 오류 반환을 생략하지
  않는다.
- 벤치마크 수치는 실행한 날짜와 소스 리비전에 묶는다. 현재 API가 바뀌었다고
  과거 측정값까지 갱신된 것은 아니다.
- `ns/id`처럼 단위가 같아도 완료 조건, 작업량, 시계, 배치, 메모리 할당 경계가
  다르면 언어 구현의 절대 우열로 해석하지 않는다.
- Snowflake처럼 시계 모델이 다른 구현은 성능 수치와 운영 동등성을 분리해
  설명한다.

### 릴리스 BOM과 개발 SNAPSHOT을 구분한다

- 릴리스 활용기는 당시 BOM이 검증한 버전 집합을 보존한다.
- 현재 `develop`의 SNAPSHOT 카탈로그는 후속 개발 상태이며, 과거 릴리스의
  구성으로 대체하지 않는다.
- 버전 목록만 나열하지 않고 커넥션 상태 복원, 캐시 운영 상태, 플러그인 수명
  주기, 입력 제한, 공급자 호환성과 같은 독자가 적용할 경계를 중심으로
  설명한다.

### 자료는 독자가 다음 판단을 할 수 있게 구성한다

- 내부 작업 기록이나 원시 산출물 목록은 제거한다.
- 현재 API를 확인할 소스, 당시 결과를 해석할 벤치마크 근거, BOM과 구성
  모듈을 확인할 링크를 남긴다.
- 한국어 독자가 링크를 열기 전에도 핵심 판단 경계를 이해할 수 있도록 본문에서
  먼저 설명한다.

### 한영 다이어그램은 각각 원본 크기로 검사한다

- 동일한 카드 폭에서도 영어 글꼴은 한국어 글꼴보다 문구가 더 넓게 렌더링될
  수 있다.
- 긴 영어 문구는 줄을 나누거나 카드 폭과 간격을 조정한다.
- 한쪽 언어가 통과했다고 다른 쪽을 대신 검증한 것으로 간주하지 않는다.
- 차트는 막대 길이를 로그 척도로 표현하더라도 실제 수치와 단위를 함께 표시해
  시각적 비율의 오해를 막는다.

## 체크리스트 반영

이번 배치에서 재사용할 수 있는 다음 규칙을 chezmoi 원본
`bluetape-writer` 한국어 교정 체크리스트에 추가했다.

- 현재 API 예제와 과거 벤치마크의 시간·리비전 경계
- 오류를 반환하는 생성자·메서드의 예제 처리
- 언어 간 벤치마크 동등성을 판단할 완료·작업량·시계·배치·할당 경계
- 최신 릴리스 BOM과 개발 SNAPSHOT 카탈로그의 구분
- 한국어·영어 다이어그램의 글자 폭을 각각 검사하는 규칙

chezmoi apply 후 원본과 live skill의 byte parity를 확인했고, dotfiles
commit `e5dd2b6`을 upstream에 push했다. 별도로 존재하던 live-owned
`config.toml`과 native subagent watchdog drift는 이번 범위 밖이므로
변경하지 않았다.

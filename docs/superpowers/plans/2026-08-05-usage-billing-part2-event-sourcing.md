# 사용량 과금 Part 2 Event Sourcing 글 작성 계획

## 목표

`bluetape4k-workshop`의 `usage-metering-billing-event-sourcing` 예제를 근거로, 과금 원장을 Event Sourcing으로 확장할 때 얻는 재생·프로젝션 이점과 함께 스키마 진화·재구축·실패 격리라는 운영 책임을 설명하는 한·영문 글을 작성한다.

## 범위

- 한국어·영문 Part 2 글을 같은 구조와 의미로 작성한다.
- Part 1의 시리즈 탐색 링크를 Part 2 실제 경로로 갱신한다.
- 기존 다크 스타일 Event Sourcing 다이어그램을 한·영문 자산으로 재사용한다.
- Part 2 전용 대표 이미지를 같은 시리즈의 시각 언어로 만든다.
- 독자가 구현을 확인할 수 있도록 Workshop의 핵심 소스와 통합 테스트만 자료로 연결한다.
- 앞선 글의 핵심 불변식은 이 글만 읽는 독자도 이해할 수 있도록 필요한 만큼 반복하고, 과금 도메인의 기준 데이터·재생·프로젝션 운영 경계에 집중한다.

## 작업 순서

1. Workshop 구현에서 Event Envelope, 낙관적 추가, 재생·스냅샷, Upcast, 프로젝션 세대 전환과 Poison Event 계약을 확인한다.
2. Part 1과 기존 관련 글을 검토해 필요한 배경을 선별해서 반복하고 Part 2의 독자 질문을 확정한다.
3. 한국어 원고를 먼저 작성하고 기술 문체와 용어 일관성을 교정한다.
4. 영문 원고를 독립적으로 자연스럽게 작성하되 구조·링크·주장의 의미를 한국어와 맞춘다.
5. 다이어그램 자산과 대표 이미지를 연결하고, 확대 제목·대체 텍스트·캡션을 로케일별로 제공한다.
6. 시리즈 링크와 독자용 구현 자료를 갱신한다.
7. 콘텐츠 계약 테스트, 다이어그램 로케일 테스트, 전체 테스트와 정적 빌드를 실행한다.
8. 로컬 프리뷰에서 한·영문 경로, 다이어그램 확대, 대화형 시각 자료 연결을 확인한다.

## 검증 기준

- 한·영문 글이 모두 빌드되고 명시적 태그가 일치한다.
- 한국어 글은 번역체·구어체를 피하고 기술 문서에 적합한 용어를 사용한다.
- 다이어그램은 한국어·영문 자산을 분리하고 다크 스타일, 충분한 가독성, 확대 제목을 제공한다.
- Part 1에서 Part 2로, Part 2에서 Part 1과 대화형 Event Sourcing 뷰로 이동할 수 있다.
- Event Store, Snapshot, Projection의 권위가 혼동되지 않으며 실패 경로와 비선택 조건까지 설명한다.
- `npm test`, `npm run build`, `git diff --check`가 통과한다.

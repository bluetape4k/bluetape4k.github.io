# 블로그·매뉴얼 기술 다이어그램 크게 보기 설계

## 상태

- 작성일: 2026-07-19
- 대상 저장소: `bluetape4k/bluetape4k.github.io`
- 대상 화면: 블로그 본문과 버전별 매뉴얼 본문
- 승인된 방향: 블로그와 매뉴얼의 대상 감지는 각각 구성하고, 확대 UI와 사용자 동작은 동일하게 유지
- 현재 단계: 초기 배포 후 콘텐츠 전체 범위 누락을 보완하는 Type C 결함 수정

## 목표

본문 폭에 맞춰 축소된 기술 다이어그램을 별도 페이지로 이동하지 않고 큰 화면에서 읽을 수 있게 한다. 블로그와 매뉴얼의 콘텐츠 구조는 서로 다르므로 대상 판별 방식까지 억지로 공통화하지 않는다. 대신 독자가 어느 영역에서든 같은 위치의 아이콘과 같은 확대·닫기 동작을 경험하도록 UI 계약을 통일한다.

## 대상과 비대상

### 확대 대상

블로그에서는 다음 `figure` 안의 이미지만 확대 대상으로 삼는다.

- `.bt4k-architecture`
- `.bt4k-chart`
- `.bt4k-sequence`

매뉴얼에서는 본문 안에서 `/manual-assets/` 경로를 사용하는 이미지와, 릴리스 README에서 공유한 immutable GitHub 다이어그램을 확대 대상으로 삼는다. README 공유형은 `bluetape4k` 조직, 동일 저장소, 동일 40자리 배포 커밋, `docs/images/readme-diagrams/` 아래의 대응 PNG·SVG 쌍이 모두 일치할 때만 인정한다. 확대 화면은 미리보기 PNG 대신 같은 배포 커밋의 SVG 원본을 사용한다.

### 확대하지 않는 대상

- `.bt4k-blog-hero`와 그 밖의 블로그 대표 이미지
- 블로그 목록의 카드 썸네일
- 일반 스크린샷과 사진
- 로고, 배지, 아이콘
- 사용자가 직접 삽입한 일반 `/assets/` 이미지

대상 여부를 이미지 크기나 파일 확장자로 추측하지 않는다. 블로그는 의미가 명시된 `figure` 클래스, 매뉴얼은 관리되는 다이어그램 자산 경로를 기준으로 판별한다.

## 검토한 접근 방식

### 1. 영역별 대상 감지와 동일 UI 계약

블로그와 매뉴얼이 각자의 DOM 구조에 맞는 로직으로 확대 대상을 찾는다. 확대 아이콘, 대화상자 구조, 색상, 여백, 닫기 동작과 접근성 규칙은 동일한 계약을 따른다.

장점은 기존 콘텐츠 파일을 대량으로 수정하지 않고도 대상을 정확히 제한할 수 있다는 점이다. 한쪽 콘텐츠 구조가 바뀌어도 다른 쪽의 대상 감지에 영향을 주지 않는다.

### 2. 블로그와 매뉴얼을 완전히 독립적으로 구현

초기 결합은 가장 낮지만 같은 UI를 두 곳에서 따로 유지해야 한다. 시간이 지나면서 버튼 위치, 접근성 문구, 닫기 동작이 달라질 가능성이 있어 채택하지 않는다.

### 3. 외부 Lightbox 라이브러리 도입

갤러리 이동, 회전, 복잡한 확대·축소 기능을 빠르게 제공할 수 있다. 현재 요구사항에는 기능과 의존성이 과도하고 사이트 번들 및 업그레이드 부담이 생기므로 채택하지 않는다.

## 결정

1번 접근 방식을 사용한다. 블로그와 매뉴얼의 **대상 감지와 초기화는 분리**하고, 확대 화면은 네이티브 `<dialog>`를 기반으로 같은 시각·동작 계약을 따른다. 공통화를 위해 콘텐츠 구조를 바꾸거나 별도 라이브러리를 추가하지 않는다.

## 사용자 경험

### 진입

- 확대 대상 이미지 위에 마우스를 올리면 `zoom-in` 커서를 표시한다.
- 이미지 우측 상단에 `크게 보기` 아이콘 버튼을 배치한다.
- 이미지 자체를 클릭하거나 아이콘 버튼을 누르면 같은 확대 화면을 연다.
- 아이콘 버튼은 마우스를 올려야만 나타나는 방식으로 숨기지 않는다. 키보드와 터치 사용자도 기능의 존재를 바로 알 수 있어야 한다.
- 버튼에는 현재 문서 언어에 맞는 접근성 이름을 제공한다.
  - 한국어: `크게 보기`
  - 영어: `View larger`

### 확대 화면

- 화면 전체에 어두운 반투명 배경을 표시한다.
- 대화상자 상단에 다이어그램 제목과 닫기 버튼을 배치한다.
- 다이어그램은 원본 비율을 유지하면서 사용 가능한 화면 안에서 최대한 크게 표시한다.
- 큰 이미지가 화면보다 넓거나 높을 때는 이미지 영역을 스크롤할 수 있어야 한다.
- 모바일에서는 브라우저의 기본 확대와 이동 동작을 방해하지 않는다.
- 이미지의 `alt`를 확대 화면의 대체 텍스트로 그대로 사용한다.
- 블로그 `figcaption`이 있으면 제목과 구분된 설명으로 확대 화면 하단에 표시한다. 매뉴얼은 별도 설명을 생성하지 않는다.
- 이미지 사이를 이동하는 갤러리 기능은 제공하지 않는다. 확대 화면은 한 번에 하나의 다이어그램만 다룬다.

### 제목과 설명

제목, 설명, 대체 텍스트의 역할을 섞지 않는다.

- **제목:** 독자가 다이어그램의 주제를 빠르게 식별하기 위한 짧은 문구
- **설명:** 다이어그램을 읽는 맥락이나 출처를 보충하는 `figcaption`
- **대체 텍스트:** 이미지를 볼 수 없는 독자에게 내용을 전달하는 `alt`

블로그는 `figure`의 `data-diagram-title`을 제목의 우선 출처로 사용한다.

```mdx
<figure
  class="bt4k-architecture"
  data-diagram-title="병원 예약 SaaS의 업무 영역"
>
```

매뉴얼의 Markdown 이미지는 별도 제목 속성을 갖지 않으므로 현재 `alt`를 제목으로도 사용한다. 매뉴얼의 대체 텍스트는 대부분 다이어그램 이름을 간결하게 표현하고 있어 현재 콘텐츠 구조와 맞는다.

제목 결정 순서는 다음과 같다.

1. `data-diagram-title`
2. 매뉴얼 이미지의 `alt`
3. 제목 영역 생략

블로그의 긴 `alt`나 설명형 `figcaption`을 자동으로 제목으로 승격하지 않는다. 파일명도 제목의 대체값으로 노출하지 않는다. 새 블로그 다이어그램에는 현지화된 `data-diagram-title`을 작성하며, 기존 블로그 다이어그램의 제목 보강은 확대 기능 구현과 분리해 필요한 글부터 점진적으로 수행한다.

### 종료

다음 입력은 모두 확대 화면을 닫는다.

- 닫기 버튼
- `Escape`
- 다이어그램 바깥의 어두운 배경 클릭

대화상자를 닫은 뒤에는 확대를 실행한 아이콘 버튼 또는 이미지 주변의 원래 위치로 포커스를 복원한다. 대화상자가 열려 있는 동안에는 배경 페이지가 스크롤되지 않게 한다.

## 구조

### 블로그 초기화

블로그 글에서 승인된 `figure` 클래스에 속한 이미지만 찾는다. 대표 이미지와 임의의 본문 이미지는 선택자에 포함하지 않는다. `data-diagram-title`이 있으면 확대 화면 제목으로 전달한다. 기존 MDX에 제목 속성을 일괄 추가하지 않는다.

### 매뉴얼 초기화

매뉴얼 본문의 `.sl-markdown-content` 아래에서 `src`가 `/manual-assets/`로 시작하는 이미지와 immutable README 미리보기 후보를 찾는다. README 후보는 런타임에서 저장소, 커밋, 안전한 상대 경로, 파일 stem이 대응 SVG 링크와 모두 같은지 다시 검증한다. 일반 원격 이미지나 GitHub 스크린샷은 선택하지 않는다.

### 동일 UI 계약

두 초기화 로직은 다음 표현 규칙을 공유한다.

- 확대 대상 이미지를 감싸는 위치 기준 요소
- 우측 상단 확대 버튼의 모양과 크기
- `<dialog>`의 제목 영역, 배경, 최대 크기와 내부 여백
- 닫기 버튼과 접근성 이름
- 캡션 표현
- 열기·닫기와 포커스 복원 규칙

코드의 재사용 단위는 구현 계획에서 현재 Astro/Starlight 컴포넌트 경계에 맞춰 결정한다. UI가 같다는 이유만으로 블로그와 매뉴얼의 대상 감지 로직을 하나의 복잡한 선택자로 합치지 않는다.

## 점진적 향상과 오류 처리

- JavaScript가 실행되지 않아도 기존 이미지와 대체 텍스트는 그대로 보여야 한다.
- 초기화가 반복되더라도 같은 이미지에 버튼이나 이벤트가 중복 등록되지 않아야 한다.
- 대상 이미지가 로드되지 않으면 기존 브라우저의 깨진 이미지와 대체 텍스트를 유지하고 확대 버튼은 동작하지 않게 한다.
- 다이어그램 하나의 초기화 실패가 페이지의 나머지 콘텐츠나 다른 다이어그램을 막지 않아야 한다.
- 외부 링크 이동이나 다운로드 동작을 이미지 클릭에 새로 부여하지 않는다.
- 검증된 README 공유 다이어그램의 기존 GitHub 링크는 DOM 향상 과정에서 제거한다. 이미지와 우측 상단 버튼은 모두 크게 보기만 수행하며, 원본 SVG는 확대 화면의 이미지 소스로 직접 사용한다.

### 주요 실패 모드

| 실패 모드 | 방지 또는 복구 |
| --- | --- |

| 임의의 GitHub 이미지가 README 다이어그램으로 오인됨 | `bluetape4k` 조직, 저장소, 40자리 커밋, 안전한 `readme-diagrams` 상대 경로와 파일 stem을 모두 비교한다. |
| 전체 화면 패널이 클릭 표면을 덮어 빈 배경 클릭으로 닫히지 않음 | 패널 여백과 이미지 viewport의 빈 영역을 명시적인 닫기 표면으로 처리하고 브라우저에서 검증한다. |

| 깨진 이미지가 빈 확대 화면을 엶 | 로드 오류가 확인된 이미지의 확대 버튼을 비활성화하고 이미지 클릭도 열리지 않게 한다. |
| 제목·캡션을 HTML로 삽입해 콘텐츠가 실행 가능한 markup이 됨 | 제목과 캡션은 `textContent`로만 전달하고 기존 이미지 URL 외의 입력을 실행하지 않는다. |

## 호환성과 운영 영향

- 매뉴얼의 기존 Markdown과 이미지 URL, `alt`는 그대로 두고 DOM을 점진적으로 향상한다. 블로그는 누락된 기술 그림과 제외할 스크린샷에 의미 클래스를 명시해 자동 판별의 입력을 고정한다.
- 외부 의존성, 서버 API, 저장소 데이터, 배포 환경 변수와 콘텐츠 스키마를 추가하지 않는다.
- 초기화 비용은 현재 페이지의 승인된 다이어그램 수에 선형이며 페이지 로드 후 한 번만 수행한다. DOM 전체 감시나 주기적 polling을 추가하지 않는다.
- 기능 제거가 필요하면 Footer의 확대 컴포넌트 마운트와 전역 stylesheet 등록을 제거하면 기존 이미지 표시로 즉시 돌아간다. 콘텐츠 migration이나 데이터 rollback은 없다.
- README, KDoc, changelog, 라이브러리 API에는 영향이 없다. 사용자에게 보이는 계약은 이 사이트의 블로그와 매뉴얼 UI에 한정된다.

## 시각 규칙

- 확대 버튼은 다이어그램과 충분한 대비를 갖는 어두운 반투명 원형 또는 둥근 사각형으로 표현한다.
- 라이트·다크 테마에서 버튼, 배경, 닫기 아이콘의 명암 대비를 유지한다.
- 확대 화면의 배경은 사이트 테마와 무관하게 다이어그램에 집중할 수 있는 어두운 계열을 사용한다.
- 다이어그램 자체에 불필요한 필터나 색상 변환을 적용하지 않는다.
- 프린트 화면에서는 확대 버튼과 대화상자를 출력하지 않는다.

## 접근성

- 아이콘 버튼은 실제 `<button type="button">` 요소를 사용한다.
- 버튼과 닫기 제어에 현재 페이지 언어에 맞는 접근성 이름을 제공한다.
- `<dialog>.showModal()`을 사용해 배경 콘텐츠를 상호작용 대상에서 제외한다.
- 대화상자를 열면 닫기 버튼으로 포커스를 이동한다.
- 키보드만으로 열기와 닫기가 가능해야 한다.
- 강제 색상 모드에서도 버튼과 대화상자 경계가 사라지지 않아야 한다.
- `prefers-reduced-motion` 사용자를 위해 필수적이지 않은 확대 애니메이션을 제거한다.

## 검증 기준

### 자동 검증

- 블로그 대상 선택자가 승인된 세 종류의 `figure`만 포함하는지 검증한다.
- 매뉴얼 대상 선택자가 `/manual-assets/`와 README 공유 후보만 포함하는지 검증한다.
- 한국어·영어 매뉴얼 전체에서 README 공유 PNG가 같은 저장소·커밋·경로의 SVG와 쌍을 이루는지 검증한다.
- 블로그 전체의 로컬 이미지가 기술 다이어그램 또는 대표 이미지·스크린샷 같은 명시적 비대상으로 분류됐는지 검증한다.
- 같은 이미지에 초기화를 두 번 실행해도 제어가 하나만 생성되는지 검증한다.
- 블로그의 `data-diagram-title`과 매뉴얼의 `alt`가 각각 제목으로 전달되는지 검증한다.
- 제목이 없는 블로그 다이어그램에서 제목 영역과 파일명이 노출되지 않는지 검증한다.
- 한국어와 영어 접근성 문구를 검증한다.
- `npm test`와 `npm run build`를 통과한다.

### 브라우저 검증

한국어와 영어의 대표 블로그 글 및 매뉴얼 페이지에서 다음을 확인한다.

1. 기술 다이어그램에만 확대 아이콘이 표시된다.
2. 대표 이미지와 일반 스크린샷에는 확대 아이콘이 표시되지 않는다.
3. 이미지 클릭과 아이콘 버튼이 모두 확대 화면을 연다.
4. 닫기 버튼, `Escape`, 배경 클릭이 모두 동작한다.
5. 닫은 뒤 포커스가 원래 위치로 돌아간다.
6. 블로그의 명시적 제목과 캡션이 서로 다른 영역에 표시된다.
7. 매뉴얼의 대체 텍스트가 제목으로 표시된다.
8. PNG와 SVG가 원본 비율로 표시된다.
9. 데스크톱과 모바일 너비에서 제목, 이미지와 닫기 버튼이 화면 밖으로 벗어나지 않는다.
10. 라이트·다크 테마와 강제 색상 모드에서 제어가 식별된다.
11. JavaScript를 사용할 수 없는 경우 기존 콘텐츠가 그대로 읽힌다.
12. README 공유형 다이어그램에서 GitHub 링크가 제거되고 이미지와 아이콘이 모두 같은 SVG 확대 화면을 연다.

## 완료 조건

- 블로그와 매뉴얼에서 승인된 기술 다이어그램만 확대할 수 있다.
- 두 영역의 확대 아이콘과 대화상자가 같은 UI와 동작을 제공한다.
- 확대 화면이 가능한 경우 다이어그램 제목을 표시하고, 제목과 설명 및 대체 텍스트의 역할을 유지한다.
- 이미지 클릭과 우측 상단 아이콘 버튼이 모두 동작한다.
- 대표 이미지와 일반 스크린샷은 영향을 받지 않는다.
- 키보드, 모바일, 라이트·다크 테마에서 핵심 동작을 검증한다.
- 기존 콘텐츠를 대량으로 수정하거나 외부 Lightbox 의존성을 추가하지 않는다.
